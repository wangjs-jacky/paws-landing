GETTING STARTED

安装与快速上手

在运行编程智能体的电脑上安装 Paws，把电脑与 Paws 账号配对，然后启动新会话或接入已有会话。

先理解 Paws 绑定了什么

Paws 让你从手机或网页控制电脑上的 Claude Code、Codex、Gemini、OpenCode 等编程智能体。

手机 / Web App │ HTTP + WebSocket · 端到端加密 ▼ 同步中继 Server │ 加密同步 · 机器在线状态 · 会话状态 ▼ 电脑上的 paws CLI / daemon ▼ Claude Code · Codex · Gemini · OpenCode

Paws 建立的是“账号 ↔ 电脑 ↔ Agent 会话”的配对关系，不是在 Git 仓库中添加项目成员。

1

安装 Agent 与 Paws CLI

先安装并登录你要使用的编程智能体。以 Codex 为例：

$ npm i -g @openai/codex $ codex # 登录并确认 Codex 可以独立运行

然后在同一台电脑安装 Paws：

$ npm i -g @wangjs-jacky/paws $ paws --version

请优先使用 paws 命令；happy 只是为了兼容旧版本而保留的别名。

获取客户端

从 GitHub Releases 下载最新 Android APK，或者使用 Paws Web App。自托管用户要确保 App 和 CLI 指向同一个 Server。

下载 Android APK 打开 Web App
2

绑定 Paws 账号

在电脑终端执行：

$ paws auth login --force

选择手机 App 登录方式，用 Paws 扫描终端二维码并确认。这一步会把电脑加入你的加密账号。

--force 会替换这台电脑原有的 Paws 身份。它用于首次配对或有意切换账号，不是每次启动都要执行的命令。

3

启动或接入 Agent 会话

启动一个新 Codex 会话

$ cd /你的/项目目录 $ paws codex

Paws 会启动 Codex、创建远程会话并让手机或网页端看到它。直接执行裸 paws 会启动默认的 Claude 会话。

接入已经运行的 Codex

如果 Codex 已经启动，不要再开一个重复会话。请让当前 Codex 会话从项目目录执行：

$ paws attach --agent codex --json # Claude Code 使用 --agent claude

不要在一个无关的新终端里执行，否则命令无法取得当前 Codex 的 Thread ID。高级用户也可以显式传入 --codex-thread-id <id>。

随后在 Paws 中打开该会话，发送一条测试消息，确认输出和权限请求都能正常同步。

4

启用手机远程新建会话

daemon 是电脑上的后台进程。它让你在没有打开 Agent 终端时，也能从 App 新建会话。运行 Paws 时通常会自动启动 daemon。

$ paws daemon status $ paws daemon start # 仅在未运行时需要

普通用户不需要 happy-daemon-rc，也不需要手工创建 ~/.local/bin。这类脚本只用于固定某台维护机器的 Node、代理、工作目录或自托管 Server。

切换用户与多人使用

在同一个操作系统用户下再次执行 paws auth login --force，表示把原账号替换成新账号，不是邀请一位新的项目协作者。

  • 一个人换账号：使用 paws auth login --force 重新扫码。
  • 多人共用一台电脑：建议使用不同的 macOS、Linux 或 Windows 系统用户，隔离各自的凭据与 ~/.happy 数据。
  • 团队共享 Git 项目：项目成员权限仍由 GitHub、GitLab 或仓库自身管理，Paws 配对不能替代项目权限。

控制会话

  • 手机接管：在 App 中打开会话并输入指令。
  • 电脑收回：回到终端按键即可恢复本地控制。
  • 远程授权：Agent 请求运行命令或修改文件时，可在手机上处理权限。
  • 发送图片：新建会话时可附加截图或照片，支持的视觉模型可以读取。

自托管

使用自托管 Server 时，CLI 与 App 必须指向完全一致的地址：

$ export HAPPY_SERVER_URL=https://your-server.example.com $ export HAPPY_WEBAPP_URL=https://your-server.example.com $ paws codex

手机端也要在设置中填写同一个 Server。生产或团队环境建议使用 HTTPS。
