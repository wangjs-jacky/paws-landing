# Paws 首页跨设备动效叙事 V2 设计规格

日期：2026-08-28

状态：聊天方案已确认，等待书面规格复核

仓库：`wangjs-jacky/paws-landing`

视觉方向：Ember Command Deck + Cinematic Marmot（方案 01 + 03）

## 1. 目标

完整重构 Paws 首页的信息叙事和滚动体验，让访问者在第一轮浏览中明确理解：

- Paws 是运行在用户电脑上的编程 Agent 的跨设备控制台；
- App 是核心移动控制端，PC 浏览器 Web 是同等重要的深度工作台；
- 用户可以远程启动、查看、补充指令和审批同一个 Agent 会话；
- 本机 daemon 负责在指定电脑和目录启动 Agent，Web/App 负责远程控制；
- Paws 支持 Codex、Claude Code、Gemini、OpenCode 与 ACP Agents；
- Paws 的 Web/同步服务可部署在阿里云或自托管环境，但底层 Agent 登录和 API 网络条件仍由对应提供商决定。

新版不以“多加几个淡入”为目标。滚动、指针、角色和产品 UI 必须共同解释真实工作流，让动效本身成为产品演示。

## 2. 成功标准

访问者无需阅读文档即可回答以下问题：

1. Paws 控制的是什么？
2. App 与 PC Web 分别适合做什么？
3. 如何从远程启动电脑上的 Agent？
4. Agent 需要权限时如何处理？
5. App 与 PC 是否共享同一个会话？
6. Paws 相比只在本机终端使用 Agent 的价值是什么？

视觉上必须达到：

- 首屏具有明确的 Paws 品牌记忆，而不是通用 SaaS 模板；
- 角色不再只有一只点赞土拨鼠，至少七套现有角色在不同章节承担语义；
- App/PC 界面有真实内容、状态与操作路径，不出现空白大卡片；
- 1440×1000 桌面和 390×844 手机均无横向溢出、遮挡或意外大空白；
- 动效关闭后，页面仍按正确顺序完整表达内容。

- 首页导航、Hero 及 Hero 终端的视觉统一；

- App 与 PC Web 高保真界面演示；

- 产品能力、价值比较、架构/阿里云、自托管和路线图内容；
- 中英文、明暗主题、移动端和减少动态效果支持；
- 既有透明主角色和 H3 转头素材的清晰度修复；
- Cloudflare Pages 构建与浏览器验证。

### 3.2 本期不包含

- 声称土拨鼠可以真正 360° 转头；

- 把概念演示伪装成已经存在的产品功能；
- 重构 `/docs` 和 `/docs/zh-CN` 文档页。

## 4. 核心叙事

首页主线采用一个完整任务生命周期：

> 在 PC Web 远程启动任务 → 实时查看 Agent 执行 → 离开电脑后在 App 审批 → 在 App 与 PC 之间接力同一个会话 → 管理多个 Agent 会话。

页面中的每个主要区块必须推进这条主线，不能只重复“远程控制”“安全”“开源”等抽象标签。

## 5. 视觉系统

### 5.1 品牌基调

- 主色：Paws Ember Orange；用于主 CTA、活动状态、滚动进度和连接信号。
- 暗色：暖黑与炭黑，不使用纯蓝黑科技模板。
- 亮色：暖白与浅沙色，保持橙色层次和角色毛发对比。
- 状态色：绿色表示在线/完成，琥珀表示等待审批，红色仅用于失败或拒绝。
- 字体：沿用 Bricolage Grotesque、DM Sans、JetBrains Mono 组合及系统中文回退。
- 边界：细描边、中等圆角、局部玻璃层；避免每个区块都是同尺寸“大白框”。
- 背景：保留 Ember DotField，章节内通过密度、亮度和聚焦区域变化推进叙事。

### 5.2 方案融合

Ember Command Deck 负责信息组织：设备、状态、连接与操作必须清楚。Cinematic Marmot 负责品牌记忆：角色以特写、探头、视差、章节换装和目光响应参与故事。

动效优先级：

1. 解释状态变化；
2. 引导视线；
3. 建立角色个性；
4. 装饰氛围。

任何装饰性动画都不能覆盖前三项。

### 6.1 角色来源与用途

从主产品仓库 `packages/happy-app/sources/assets/images/mascots/` 复制并版本化以下透明 PNG 到 landing 的 `public/assets/mascots/`：

| 文件 | 章节角色 | 页面语义 |
| --- | --- | --- |
| `astro.png` | 宇航员 | 远程启动、跨越距离 |
| `explorer.png` | 探险家 | 离开电脑、随处继续 |
| `hoodie.png` | 程序员 | Agent、工具调用、代码执行 |
| `ninja.png` | 忍者 | 权限审批、安全决策 |
| `scientist.png` | 科学家 | 加密同步、系统架构 |
| `barista.png` | 咖啡师 | PC Web 深度工作台 |

黑卫衣点赞角色仍是 Hero 的主品牌锚点，不被七角色中的 `hoodie.png` 替代。

### 6.2 角色一致性策略

现有角色服装和渲染风格存在差异，因此不把它们描述为同一角色的连续动作帧，而定位为“Paws Crew”成员。统一方式包括：

- 相同的暖黑舞台、橙色轮廓光和阴影方向；
- 相同的角色卡比例、裁切基线和最大高度；
- 相同的章节标签与动效节奏；
- 不在角色图片上叠加生成式文字或额外徽标；
- 角色只在与其语义对应的章节出现，避免无意义堆图。

### 6.3 Hero 转头清晰度

复用已付费的 `artifacts/mascot-motion/h3-output.mp4`，不创建新任务。重新从 768×768 原视频提取 24 帧，生成 6×4、单帧 768×768 的透明 WebP 图集，替换当前单帧 512×512 图集。

要求：

- Hero 角色桌面 CSS 显示宽度不超过 520px；
- 图集 Alpha 边缘去除绿色溢色；
- 中心静态图使用 1254×1254 透明源图；
- 指针仅控制已有左右头部/视线范围，不宣称 360°；
- 触屏和 reduced motion 使用高清静态图；
- 图集失败时无布局跳动地回退静态图。

## 7. 首页信息架构

### 7.1 固定导航

包含：品牌、产品能力、工作方式、App + PC、开源与自托管、文档、GitHub、语言按钮、主题按钮、开始使用 CTA。

- 桌面使用单行悬浮导航，所有控件共享 44px 高度和中心线；
- 语言按钮显示目标语言，中文状态显示 `EN`，英文状态显示 `中文`；
- 手机使用完整菜单，不隐藏文档、GitHub 或语言/主题入口；
- 导航滚动到下一章节时缩小高度，但不改变按钮位置和顺序。

### 7.2 Hero：跨设备控制台

目的：在 5 秒内说明产品身份。

内容：

- 眉题：开源 · 运行在你的电脑上；
- 主标题：表达“电脑上的编程 Agent，随时触手可及”；
- 正文：手机 App 与 PC 浏览器可远程启动、查看和审批电脑上的 Agent 会话；
- 主 CTA：开始使用；
- 次 CTA：查看 GitHub；
- 保留真实终端打字交互和复制安装命令；
- 右侧使用高清黑卫衣角色，指针控制头部/视线；
- 宇航员、忍者、科学家作为小型轨道成员出现，建立 Paws Crew 概念。

Hero 不放置不透明黑色图片方框，不出现单独的大白安装卡片。

### 7.3 支持 Agent 轨道

展示 Claude Code、Codex、Gemini、OpenCode、OpenClaw 与 ACP Agents。

替换现有底部奇怪的播放按钮滚动条：

- 使用无播放按钮的 `AgentMarquee` 组件；
- 桌面自动缓慢循环，悬停或键盘聚焦时暂停；
- 用户可横向拖动或滚轮浏览；
- reduced motion 与手机默认静态换行；
- 所有名称始终可读，不用模糊、倾斜或高速滚动；
- 不展示虚构公司 Logo、用户数或背书。

### 7.4 跨设备四幕故事

该区块是首页核心，用 GSAP ScrollTrigger 固定舞台并通过滚动切换四幕。

#### 第一幕：远程启动

PC Web 显示真实结构的新建会话界面：

- 在线机器：`Mac mini · 在线`；
- 项目：`paws`；
- Agent：`Codex`；
- 模型/推理强度：可见但不夸大；
- 首条指令和发送动作。

用户滚动后，机器节点和本地 daemon 被点亮，新会话进入运行中。

#### 第二幕：查看执行

PC Web 从新建页过渡到会话页，显示：

- 用户消息；
- Skill 状态；
- 工具调用；
- 子 Agent 生命周期；
- 运行中/完成状态；
- 会话列表中的 Agent、项目和机器信息。

该幕回答“编程过程是不是黑盒”。

#### 第三幕：手机审批

视觉焦点从 PC 移向 App：

- 会话变为“等待批准”；
- App 弹出真实权限卡，例如 `npm run build`；
- 操作包括批准一次、当前会话允许、拒绝/停止并说明；
- 批准后状态变绿，执行继续；
- 不展示真实产品不存在的万能权限或后台能力。

忍者角色在该幕承担引导，动作使用现有静态透明图的探头、缩放与轻微视差，不伪装为视频动画。

#### 第四幕：跨端接力

App 与 PC 同时显示同一个会话 ID、项目和最新消息：

- 控制权连接线从 App 流回 PC；
- 消息时间线保持一致；
- 文案明确“同一个会话，不是复制一份聊天”；
- 最后展开多会话总览，展示运行中、等待批准、空闲、完成和失败。

### 7.5 App 与 PC 双控制台说明

四幕故事之后使用非固定布局总结两端分工。

App：

- 快速检查任务状态；
- 远程审批高风险操作；
- 离开电脑时追加指令；
- 处理少量、即时、需要决策的操作。

PC Web：

- 无需额外桌面客户端，通过浏览器进入；
- 新建和管理多会话；
- 查看长对话、工具调用和子 Agent；
- 适合长文本输入与深度工作。

两端是互补入口，不能把 PC Web 写成 App 的降级版，也不能弱化 App 的核心价值。

### 7.6 产品能力

用有内容的案例模块替代空卡片：

1. 远程启动：展示机器、目录、Agent 和启动结果；
2. 实时过程：展示工具调用和子 Agent 状态；
3. 权限审批：展示等待、批准和继续执行；
4. 多会话总览：展示项目分组与状态；
5. 加密同步：用拓扑图解释端到中继的数据流；
6. 开源自托管：链接 GitHub 和部署文档。

每个模块至少包含一个真实状态、一段结果导向文案和一个明确视觉证据，禁止只有图标、标题和一行泛化描述。

### 7.7 价值比较

使用问题导向的比较表，不攻击其他工具：

| 使用方式 | 本机终端直接使用 | Paws |
| --- | --- | --- |
| 离开电脑后查看 | 需要返回电脑或自行配置远程方案 | App/PC Web 查看同一会话 |
| 权限请求 | 在终端前处理 | 可在 App/Web 远程批准或拒绝 |
| 多 Agent 总览 | 分散在多个终端窗口 | 一个跨设备控制台统一显示 |
| 启动新任务 | 通常需要操作目标电脑 | 在线机器可通过 Web/App 远程启动 |
| 部署选择 | 取决于单个工具 | Paws 服务可开源自托管 |

对 Codex 的中国网络表述必须使用：

> Paws 的 Web 与同步服务可部署在阿里云，国内访问路径更可控；底层 Agent 的账号登录与 API 网络要求仍取决于对应服务提供商。

### 7.8 架构与部署

用滚动拓扑图展示：

`App / PC Web → 加密同步服务 → 用户电脑上的 Paws daemon → Codex / Claude Code / Gemini / OpenCode / ACP Agent`

要求：

- 明确 daemon 在用户电脑上运行；
- 明确远程启动需要目标机器在线；
- 区分 Paws 服务部署位置和 Agent 提供商网络；
- 提供阿里云部署、自托管文档和 GitHub 链接；
- 不展示未经验证的端到端加密算法名称、延迟或可用率数字。

### 7.9 开源与路线图

已实现内容与路线图必须视觉区分。

已实现：App、PC Web、CLI/daemon、支持的 Agents、远程审批、跨端会话、自托管。

路线图：

- 浏览器优先继续增强；
- Chrome 插件更新；
- 更丰富的角色动作和动效资产；
- 不把新的桌面 App 封装列为当前方向。

Chrome 插件只能标记为“计划中”，不能出现下载按钮或已发布版本号。

### 7.10 最终 CTA 与页脚

重复一次安装命令与开始使用入口，并包含中英文文档、GitHub、隐私和自托管链接。页脚不展示虚构采用数据、公司 Logo 或未经仓库许可文件支持的许可证声明。

## 8. 产品 UI 演示实现

### 8.1 不使用低清放大截图

现有 `docs/pr-evidence` 截图仅作为设计和回归证据，不直接作为大尺寸生产画面。生产页使用 React 重建高保真缩略界面：

- 结构、标签、状态和按钮来自真实产品源码与中文翻译；
- 保留可识别的导航、会话列表、聊天区、工具卡和权限卡；
- 删除与故事无关的小文字，避免缩小后噪声；
- 所有文字使用 DOM 渲染，保证清晰、中英文切换和无障碍；
- 演示数据集中管理，不连接真实账号或会话；
- 组件必须标注为产品演示，不能让访问者误认为已登录控制台。

### 8.2 状态模型

`CrossDeviceStory` 使用纯数据定义四幕：

```text
start    -> machine online, compose ready
watch    -> agent running, tools and subagent visible
approve  -> permission pending, mobile owns focus
handoff  -> permission resolved, same session on both devices
```

滚动只驱动当前幕的索引和过渡进度。React 状态保存语义状态，GSAP 只负责表现层，不把产品状态藏在时间线内部。

## 9. 动效架构

### 9.1 依赖与用法

新增固定版本的 `gsap` 和 `@gsap/react`。所有 React 动效通过 `useGSAP` 建立，并使用组件根节点 `scope`。ScrollTrigger、时间线、事件监听和 matchMedia 上下文在卸载时必须自动清理。

保留 React Bits 的 Ember DotField 和 SpotlightCard 作为局部视觉组件，不引入完整 React Bits 运行时。

### 9.2 动效章节

- Hero：DotField 指针扰动、角色目光跟随、Paws Crew 轨道轻微视差；
- Agent 轨道：无播放按钮的可暂停循环；
- 四幕故事：桌面 pin + scrub；设备焦点、连接线、UI 状态和角色同步换场；
- 能力模块：文字先于装饰进入，案例 UI 后进入；
- 价值比较：逐行高亮差异，不做高速数字滚动；
- 架构图：数据包沿拓扑线推进，节点到达后显示解释；
- 章节过场：角色从边缘探头或换位，不做无依据的 3D 旋转。

### 9.3 响应式行为

桌面（≥1024px）：允许 pinned story、scrub、指针跟随和横向角色轨道。

平板（768–1023px）：故事舞台不长期 pin；每幕作为连续卡段，设备仍保持并列或错层。

手机（<768px）：

- App 画面优先，PC 画面缩小为上下文；
- 四幕按垂直顺序展示，不依赖长距离 pin；
- 角色保持在内容附近，不在首屏下方制造大空白；
- Agent 轨道静态换行或可手动横滑；
- 禁止因视差扩大页面宽度。

### 9.4 减少动态效果

`prefers-reduced-motion: reduce` 下：

- DotField 静态；
- Hero 使用高清静态角色；
- 四幕变为四个完整静态章节；
- Agent 名称静态换行；
- 架构连接线直接显示最终状态；
- 终端直接显示完整文本；
- 不使用自动循环、scrub 或持续漂浮。

- 单个组件超过约 250 行时继续拆分，避免把全部时间线写回 `App.jsx`。

## 11. 中英文和主题

- 首次访问跟随浏览器语言，`zh-*` 使用简体中文，其余使用英文；
- 用户选择存入现有版本化 preference key；
- 所有产品 UI 演示文字、状态、按钮和辅助说明一起切换；
- 语言切换不重建 ScrollTrigger 到错误位置，内容更新后调用一次受控 `ScrollTrigger.refresh()`；
- 首次主题跟随系统，显式选择持久化；
- 暗色和亮色均使用相同信息层级，亮色不能出现透明图绿边、低对比连接线或大白空卡；
- 文档链接继续分别指向 `/docs` 与 `/docs/zh-CN`。

## 12. 内容准确性

首页文案以以下产品证据为准：

- 会话状态与管理：`SessionRowChrome.tsx`；
- 新建会话参数与在线机器：`ComposeHome.tsx`；
- daemon 远程启动：`packages/happy-cli/src/daemon/run.ts`；
- 工具、Skill 和子 Agent 展示：`ChatList.tsx`；
- 权限批准/拒绝：`PermissionFooter.tsx` 与 `sync/ops.ts`；
- local/remote 控制权和消息补拉：`sync/ops.ts` 与 `sync/sync.ts`；
- 中英文产品说明：`README_CN.md` 与翻译文件。

任何超出上述证据的新卖点必须在加入首页前重新核对源码或文档。

## 13. 性能预算

- 首屏关键静态图片合计压缩后目标 ≤ 1.8MB；
- Hero 高清转头图集目标 ≤ 3MB；若超过，优先调整 WebP quality，不降低到明显模糊；
- 非首屏七角色和产品模块图片使用 `loading="lazy"` 与明确尺寸；
- GSAP/ScrollTrigger 只在需要的断点加载/初始化对应时间线；
- 每个指针帧最多一次布局读取，位置更新使用 transform/CSS 变量；
- 页面不可见或章节离屏时停止持续 RAF；
- DotField DPR 最高 2，移动端降低密度；
- 字体失败时不产生严重布局跳动；
- 所有媒体预留宽高比，累计布局偏移目标接近 0。

## 14. 无障碍

- 语义化 header、main、section、nav 和 footer；
- 标题层级连续，每幕都有可访问标题；
- 装饰角色使用空 alt，承担信息的角色提供本地化 alt；
- 产品 UI 演示对读屏器提供简洁文本摘要，不逐个朗读装饰性缩略按钮；
- 所有链接、菜单、语言、主题、复制和 CTA 可键盘操作；
- 焦点状态在明暗主题均清晰；
- 最小触控区域 44×44px；
- 自动 Agent 轨道可暂停；
- 不通过颜色或动画单独表达运行/审批/完成状态；
- reduced motion 下不损失任何卖点内容。

## 15. 失败与降级

- GSAP 或 CDN 不可用：核心页面静态顺序正常，正式构建不得依赖 CDN；
- ScrollTrigger 初始化失败：四幕显示为普通垂直章节；
- 角色图片失败：保留文字和产品 UI，不显示破图占位；
- Hero 图集失败：回退高清静态 PNG；
- Clipboard 失败：提供选择文本的后备方式，并只在成功时播报成功；
- localStorage 不可用：使用系统语言/主题和当前会话状态；
- WebGL/canvas 不可用：DotField 回退静态 CSS 点阵；
- 内容高度变化：受控刷新 ScrollTrigger，不在 resize 循环中重复创建时间线。
